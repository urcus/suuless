Supporting reduction and cessation

Web and Android share a personal plan: observation, reduction with dated goals, or quitting on a chosen date. SQLite stores each account’s motivation, coping strategy and reminder preferences. The interfaces support English, French and Japanese.

One craving, one outcome

The widget opens the craving flow directly. A pause suggests walking, drinking water, breathing or distraction. The user chooses the outcome; the timer never decides for them.

Data and calculations

journeys stores versioned plans; stale writes return 409 plan_conflict. cravings stores UTC timestamps, triggers, strategies and final outcomes. A partial unique index permits only one pending craving per account. checkins stores confirmed totals by local date and time zone.

Adding or deleting entries invalidates affected confirmations, including those made in previous time zones. Empty days are not automatically confirmed. Progress compares a fixed baseline with explicitly confirmed completed days; monetary estimates retain historical currencies without conversion.

See the coaching guide for baseline selection, weekly comparisons, quit counters, reminders and support resources. See API usage and the OpenAPI contract for all operations and schemas.

Reminders and validation

Reminders are opt-in. Web reminders require a visible interface. Android uses JobScheduler with network access and notification permission; scheduled times are preferences, not exact alarms. Quiet hours and local-date deduplication apply, including DST transitions. Signing out cancels local reminders.

Tests cover account isolation, conflicts, concurrent requests, UTC/DST, baselines and export in tests/test_coaching.py, browser flows in tests/web-coaching.mjs, and reminder timing in tests/java/ReminderPolicyTest.java.
